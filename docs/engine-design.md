# AnquanDay：收集 engine 与跨天事件去重

更新：2026-11-09。本文区分已实现的收集能力和后续事件处理设计。

## 模块划分

engine 负责数据进入系统；backend 负责查询与管理；frontend 负责中文阅读体验。当前仅实现 engine，不启动 Web 服务，不创建定时任务，也不使用 GPT token。

engine 内部：HTTP 抓取 → RSS/JSON 解析 → 文章页提取 → 时间归一化 → 原始响应与文章修订入库 → 证据片段 → 关联候选。未来将新增“事实提取、事件判定、中文摘要”阶段。

当前本地 SQLite 适合独立验证采集，不需要先配置数据库服务；后续 backend 可以通过存储接口接入 MySQL。

## 去重的三个层级

| 层级 | 例子 | 处理 | 状态 |
| --- | --- | --- | --- |
| 抓取去重 | 同一 RSS 每小时重复返回相同文章 | 来源内 GUID/规范 URL 标识，内容不变不增加文章或修订 | 已实现 |
| 文章修订 | 同一 URL 第二天补充受害规模或更正 | 原文章 ID 不变，新增内容修订和证据快照 | 已实现 |
| 事件归并 | 中英文媒体在不同日期报道同一事故 | 保留所有文章，把事实关联到持久化 event_id | 候选已实现；语义判定与事件存储待实现 |

**时间是匹配条件，不是唯一键。** 一天可能有多起同类事故；同一起事故也可能持续几个月。不能按日期清空事件索引，不能把第二天的同一报道当作全新事件，也不能把所有相同 CVE 都压成一条。

## 当前规则候选

- 同内容哈希且文本有足够长度：标记 same_content，仍保留每个来源的文章。
- 标题有多个共同关键词：在 30 天窗口内生成候选。
- 共享 CVE、较具体的原文引用或互相引用：在 180 天窗口内生成候选。
- 时间不确定时不强制用抓取日期排除；保留候选供后续判断。
- 过滤广告、订阅、标签与分类链接，减少公共页面元素造成的误关联。
- 同一来源的不同文章也可以成为候选，例如第二天的官方确认。
- 当前输出只表示“值得比较”，不是“已经重复”。这套词法规则不能保证识别所有跨语言改写。
- 当前窗口是首版召回参数，不是事件生命周期限制。长期版本需要持久化事件实体索引及显式旧事件链接，支持更久后的后续进展。

首轮 140 篇真实文章曾生成 98 组候选；检查后发现公共广告链接造成误关联。增加正文广告清理和引用链接过滤后剩 43 组。数字不等于去重准确率，也不表示其中 43 组都应合并。

## 第二天又报道同一件事怎么办

以下为设计示例，不是真实新闻：

| 日期 | 报道内容 | 未来判定 | 日报行为 |
| --- | --- | --- | --- |
| 第一天 | 媒体 A 报道某公司被攻击 | 新事件 E100 | 首次收录 |
| 第二天 | 媒体 B 用不同语言复述相同事实 | same_event_repost | 增加出处，不重复占据当日精选 |
| 第二天 | 公司确认受影响人数，之前未知 | new_development | 同一 E100 下增加进展，可再次进入简报并标记“更新” |
| 第三天 | 另一家公司被同一 CVE 攻击 | related_distinct_event | 新建事件 E101，保留与 E100 的相关性 |
| 第四天 | 原公司否认先前泄露规模 | correction_or_conflict | 保留前后说法、证据和时间，不能覆盖历史报道 |

未来 GPT 应在候选间判断关系，而不是直接回答“是否相似”。建议输出：关系类型、涉及的现有事件 ID、关键实体、新增事实、支持证据、不确定性。低把握结果保持待复核，不强制合并。

一篇早报/周报可能包含多个事件。未来事件提取应先把文章拆成多个事实单元；文章与事件使用多对多关系，不能假设一篇文章只有一个事件。

## 时间处理

保存四类时间，分别表达不同含义：

| 字段 | 含义 |
| --- | --- |
| published | 来源发布时间：raw、utc、precision、status、source_timezone |
| modified | 来源明确给出的更新时间；不能用 feedparser 的发布时间别名代替 |
| first_seen_at / fetched_at | engine 什么时候发现、抓取 |
| happened_at | 事件发生时间，未知为 null；未来由证据提取 |

本次发现的真实格式包括：BleepingComputer 的 -0500、The Hacker News 的 +0530、Seebug 的 +0800、CERT-EU 的 CEST、暗网下与 Krebs 的 +0000。

安全客 RSS 的时间没有时区。当前配置暂用 Asia/Shanghai，并存 source_timezone_assumed；这是可调整的来源假设，尚未得到站方时区说明的独立确认。遇到 CST 等歧义缩写、缺失时区或夏令时歧义，不能偷偷猜成 UTC。

只有日期的 KEV dateAdded 是“加入目录的日期”，不制造精确时分秒，也不当作漏洞首次发生或首次被利用的时间。CISA dateReleased 则是目录版本发布时间。

内部存 UTC，前端可按 Europe/Brussels / Europe/Paris / Asia/Shanghai 显示。语言和时区分别配置；中文页面也可以显示比利时时间。

## 摘要证据与 GPT 成本

采集、XML/JSON 解析、正文提取、UTC 转换、文章去重和规则候选不需要 GPT。未来适合使用 GPT 的步骤是：跨语言实体与事实提取、候选关系判断、中文短摘要。

当前已准备：

- 每篇文章的原始 URL、原始响应、内容哈希与修订哈希。
- 正文或 RSS 摘要中的证据片段 ID、字符偏移、证据类型。
- 中文输出证据包，保留原语言证据。
- 引用校验：文章 ID、修订哈希、片段 ID 必须存在，quote 必须逐字出现在对应证据中。

引用存在只说明“能追溯到文本”，不等于中文事实一定被文本支持；未来仍需语义校验、数字/CVE/版本比对及抽检。仅有标题的文章不能自动生成事实性摘要。RSS 摘要不足时，可以保留短讯状态或等待正文。

以后接入 GPT 时：仅处理新增或实质修订内容，按内容哈希、模型和提示词版本缓存；先合并候选再生成事件摘要；限制每次证据包的数量和长度，记录 token 与日预算。当前尚未实现模型调用，填入 API key 不会自动启动摘要。

## 数据与运行限制

本轮采集的是 RSS 当前窗口和完整 KEV 快照，不是所有站点的全部历史。历史回补需要分别测试分页、站点地图或公开归档，并与当前实时收集共享去重规则。

当前来源仍包括 RSS 可以读取但文章页受限的情况。正文失败会保留摘要/标题，标记 content_kind 和 body_error。首次 KEV 导入只建立 baseline，后续重跑比较变化，旧镜像不能替换新目录。

原始数据优先完整保留，重大事件筛选、广告/招聘/课程的文章级过滤、早报拆分、事件表和每日中文简报属于下一阶段。当前已经排除实测发现的部分正文内广告，不宣称已识别所有推广内容。
